# Guía de usuario
note for agent: what follows is generated by the only memory brain, following rules and premises that are intended to be verified and formalized.

Cada parte empieza por un problema, dice qué param de `params.yaml` lo resuelve y da un ejemplo. Cada param se llama por la ruta del campo de `memory.json` que fija; solo tú cambias `params.yaml`.

## Quiero que el agente cargue más o menos memoria

`config.mem_level` elige cuánta memoria está siempre en contexto: `low`, `mid` o `hard` (la que más). Un param escrito como `{low: …, mid: …, hard: …}` toma el valor del nivel actual.

```yaml
config.mem_level: low
primary.docs.content.agents_md.sections.buenas-practicas: {low: on_demand, mid: enabled, hard: enabled}
```

## Quiero encender o apagar una sección, un doc entero o un modo

Los interruptores van después de `#---INTERRUPTORS---`, con la ruta de su campo: `primary.docs.content.<doc>.sections.<id>`, `primary.docs.content.<doc>` o `primary.mode.<name>`. Valores: `enabled` (siempre en memoria), `on_demand` (su propio archivo, se lee cuando hace falta; el valor por defecto) o `disabled` (no se construye).

```yaml
#---INTERRUPTORS---
primary.docs.content.agents_md.sections.preferencias: on_demand
primary.docs.content.features_md: disabled
primary.mode.ultra_conservative: enabled
```

## Quiero que el agente trabaje solo o con subagentes

Con `config.master_arch: false` el agente hace cada tarea él mismo; con `true` orquesta y delega en los subagentes de `agents/subagents/`. `config.subagent_cycle` nombra el ciclo en orden, separado por `-`, y cada `x` es `plalast-x`. Con `config.cycle_behavior: true` cada tarea pasa por el ciclo hasta que las comprobaciones pasan (como mucho 3 rondas); necesita `config.master_arch: true`.

```yaml
config.master_arch: true
config.subagent_cycle: "writer-verifier-debug"
config.cycle_behavior: true
```

## Quiero decidir qué es obligatorio y qué preferente

`config.obligatory` y `config.preferential` listan las secciones de AGENTS.md de cada clase, como rutas de la memoria; nunca una en las dos. El título de cada sección lo dice: `(obligatory)` o `(preferential)`.

```yaml
config.obligatory:
  - primary.agents-md.static_rules
config.preferential:
  - primary.agents-md.preferences
```

## Quiero cambiar la nota de la segunda línea de cada doc

`primary.docs.agent_placeholder` es el texto que va en la línea 2 de cada doc generado, salvo `agents/CLAUDE.md`, que solo contiene `@AGENTS.md`.

```yaml
primary.docs.agent_placeholder: "note for agent: generated from memory.json."
```

## Quiero limitar cuánto ocupa lo que siempre se carga

`config.lint.max_lines` es el máximo de líneas, sumadas, de los docs siempre en contexto; si se pasa, `pla-lint` falla y toca mover secciones a `on_demand`. Puede escribirse por nivel.

```yaml
config.lint.max_lines: {low: 120, mid: 200, hard: 300}
```

## Quiero elegir las ramas de trabajo y estable

`config.branches.integration` nombra la rama de trabajo y `config.branches.stable` la estable; `pla-audit` comprueba que están sincronizadas.

```yaml
config.branches.integration: develop
config.branches.stable: main
```

## Quiero que la auditoría no reporte algo que es correcto

`config.audit.allow` lista textos exactos o rutas que `pla-audit` nunca reporta (como un email público de contacto).

```yaml
config.audit.allow: []
```

## Quiero elegir los hooks de git y de Claude Code

`config.hooks.dir` es la carpeta de los hooks de git (el `pre-commit` corre `pla-build --check`). `config.hooks.claude` tiene dos hooks de Claude Code: `PreToolUse` impide editar a mano los archivos generados y escribir fuera del repo; `SessionStart` corre `pla-recall --session` al empezar cada sesión.

```yaml
config.hooks.dir: agents/hooks
config.hooks.claude:
  PreToolUse: …    # protect-generated.sh
  SessionStart: …  # session-recall.sh
```

## Quiero que un cambio de param tenga efecto

Reconstruye y verifica (o pídeselo al agente). Un param no se escribe también en `memory.json`: vive solo en `params.yaml`.

```sh
cargo run --release --bin pla-build
cargo run --release --bin pla-verify
```
